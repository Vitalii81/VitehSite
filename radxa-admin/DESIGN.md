# Адмінка на Radxa: проєктний план

Власник редагує сайт приватно на Radxa, дивиться результат на окремому порту й лише тоді публікує з основного ПК.
Публічний сайт і Worker лишаються як є (окрім нового `/api/form`), у інтернеті адмінки немає.

```
браузер (LAN/tailnet) -> nginx :8082 (адмінка) -> CGI python3 -> чернетка -> збірка -> builds/<id>/
                      -> nginx :8081 (перегляд зібраного)
основний ПК: deploy-from-radxa.sh -> ssh+tar -> перевірка sha256 -> deploy-worker.sh --source -> Cloudflare
```

## Що де лежить на Radxa
- `/srv/fwportal/admin/` код (CGI, бібліотека, UI), `/srv/fwportal/admin-secret/` пароль-хеш і ключ сесій (0700).
- `/srv/fwportal/staging/viteh-site/`: `draft.json` (одна чернетка), `uploads/` (фото і .glb), `builds/<дата>-<id>/` (пакети, 20 останніх), `state.json`.
- Вихідні файли сайту (репозиторій) лежать у `/srv/fwportal/staging/viteh-site/src/` (`git pull` або rsync); збірка бере їх звідти.

## Пам'ять і процеси
- Жодного демона: nginx + CGI `python3` (лише stdlib). Один запит ~15-30 МБ (інтерпретатор + JSON до кількох сотень КБ); збірка читає файли потоками.
- Одночасно один запис: `flock` на чернетці й збірці, атомарні записи (`tmp` + `rename`), `Content-Length` обмежено (5/8 МБ для файлів, 1 МБ для JSON).

## Безпека
- Слухає лише `127.0.0.1` і tailscale-адресу; без тунелю `viteh-lab`. Окремий вхід: довга фраза, PBKDF2-хеш у окремому файлі, `HttpOnly` + `SameSite=Strict` cookie, 5 спроб на 15 хв, перевірка `Origin` і заголовка `X-Vadmin`.
- Файли: лише JPEG/PNG/WebP/AVIF і `.glb` з перевіркою сигнатури, випадкові імена, SVG відхиляється. Тексти екрануються, дозволено абзаци, **жирний**, `[посилання](url)` і списки.

## Збірка пакета
- Чернетка + файли репозиторію -> пакет: вимкнені розділи/послуги/картки/віджети прибираються з HTML і з JSON (не ховаються CSS); сторінки з блоків рендеряться статично; `sitemap.xml` лише з увімкнених сторінок; `forms.json` для Worker.
- Перевірка перед збіркою (помилки списком) і сканування: жодного зовнішнього `https://` у ресурсах пакета.

## Публікація й відкат
- Radxa не знає секретів Cloudflare. «Опублікувати» показує команду `./deploy-from-radxa.sh <id>` (скачує пакет по ssh, звіряє sha256, викликає `deploy-worker.sh --source`, потім позначає `published`).
- Відкат: будь-яка з 20 версій повертає чернетку до знімка цієї збірки або публікується повторно за її id.

## Що відкотиться при помилці
- Інсталятор: бекап nginx-конфігу, `nginx -t`, порівняння відповідей основного порталу до/після, автовідкат при будь-якому FAIL, `--uninstall`.
- Збірка: пакет пишеться в `builds/.tmp-*` і лише після успіху перейменовується, збій нічого не змінює.
- Якщо `draft.json` відсутній або зламаний, збірка бере заводський `data/site.json`.
