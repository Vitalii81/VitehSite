# ViTeh Site

Lightweight multilingual static website for `viteh.org`: software and electronic-device
development (light to medium complexity) and AI-agent integration.

No build step, no external requests (no CDN, fonts, analytics or cookies) — GDPR-friendly by design.

## Contact form

The form posts JSON to `/api/contact` on the same origin. The Worker in `worker/` checks the fields (length limits, e-mail syntax,
consent, a hidden honeypot field, a minimum fill time, the `Origin` header) and sends a plain-text mail through Cloudflare Email Routing
(`send_email` binding `MAIL`, which can only send to the verified destination address) with the visitor's address as `Reply-To`.
Up to 3 documents (5 MB each, 10 MB in total; PDF, images, Word, Excel, text) can be attached: the form then posts multipart/form-data, the Worker checks the extension AND the first bytes of each file, sends them as attachments of the letter and puts them into the queue on the Radxa (documents first, the description last).
No password or API key is involved. Only `/api/*` runs the Worker (`assets.run_worker_first`); everything else is static.
Tests: `node --test worker/contact.test.mjs`. Deploy: `viteh-site/deploy-worker.sh` of the Server repository.

This site is independent from NanoKVM and from the OTA file server.

- `viteh.org` is the public showcase.
- `fw.viteh.org` is the technical firmware/file delivery endpoint for devices.

## Admin on the Radxa

The owner edits the site privately on the Radxa (LAN/Tailscale only, nothing in the public internet), previews the built package on a separate port, and publishes
from the main PC with the existing `deploy-worker.sh`. Cloudflare credentials never touch the Radxa.

- Switch sections, services, project cards, widgets and effects on or off (removed from the HTML, not hidden by CSS); replace photos and `.glb` models; edit all texts in uk/en/de.
- Build pages from a block library and templates (`/s/<slug>/`), create forms from templates; a pre-build check lists every problem and builds nothing until it is fixed.
- Backend: nginx + a short-lived `python3` CGI (standard library only, about 17 MB per request, no daemons). History of the last 20 builds with draft rollback.
- If no draft exists (or it is damaged) the build reproduces the factory site exactly.

Start with `radxa-admin/ADMIN.md` (install, login, daily work, publish, rollback, what could not be verified without a real Radxa, owner checklist).
Try it locally: `python3 radxa-admin/dev-server.py`.

## Design

Calm teal/indigo palette with automatic light and dark theme (follows the system, manual toggle is
remembered). Language is chosen from `?lang=`, then the saved choice, then the browser language, then English.

## Languages

The initial languages are:

- `uk` Ukrainian
- `en` English
- `de` German

Interface text lives in `data/site.json` (each text is an object `{ "uk": ..., "en": ..., "de": ... }`).
Product text lives in `data/products.json`.

To add another language:

1. Add a language entry to `data/site.json`:
   ```json
   { "code": "pl", "label": "Polski" }
   ```
2. Add `pl` text to every translated object in `data/site.json` and add a `short` code (e.g. `PL`).
3. Add `pl` text to product fields in `data/products.json`.

## Products

Add product cards in `data/products.json`.
Each card supports translated `title`, `summary`, `status`, plus `category`, `image`, `tags`, and an optional `model`
(see "3D gallery"). Cards without `model` work exactly as before.

## 3D gallery

`assets/gallery3d.js` is a progressive enhancement over the product cards **and the service cards**. An item with `"model": "assets/models/<name>.glb"`
(products in `data/products.json`, services in `data/site.json` → `services.items`) gets a "3D" button over its picture. A rendered poster
(`"poster": "assets/posters/<name>"` → `<name>-light.webp` / `-dark.webp`, chosen by theme) replaces the flat picture right away, even without WebGL.

- **Lazy:** the library ([`<model-viewer>`](https://modelviewer.dev/), about 1.0 MB, 289 KB gzip) is imported only when a 3D card is at least 55 % visible,
  or on the first press of a 3D button when Data Saver is on or the connection is 2G.
- **One scene at a time:** a single shared viewer moves to the most visible card (or the hovered/focused one) and into the dialog, across products and services.
  Clicking a card opens a `<dialog>` with rotate/zoom; `Esc`, the close button or a click on the backdrop closes it.
- **Look:** `assets/viewer-settings.js` is the single source of the viewer attributes (studio lighting from `assets/env/studio.hdr`, neutral tone mapping,
  soft shadows, limited orbit and zoom). The poster tool uses the same file, so a poster matches the live scene.
- **Fallbacks:** no WebGL, a failed script or a failed model keep the poster/flat picture; without WebGL one neutral note appears under the first grid.
  `prefers-reduced-motion` disables auto-rotation. Labels (`ui.gallery3d`) exist for `uk`, `en`, `de`.
- **Theme:** materials named `accent*` take the colour of `--accent` and follow the light/dark theme. **Privacy:** no third-party requests; only `assets/models/<name>.glb` paths are accepted.

### Procedural models, environment and posters

Models are generated, not drawn (`node tools/make-models.mjs`): rounded boxes and lathe solids with smooth normals on the bevels, instanced components,
PBR materials, and small generated PNG textures (solder mask, silkscreen, screens). Seven models: Cronos controller v1 and v2 (real GLB exported from Blender, with an optional per-card `orbit` start camera in `data/products.json`), custom board, sensor node (projects) and
software laptop, electronics in an enclosure, AI network (services). Each is below 400 KB (budget 600 KB; a test enforces it) and byte-for-byte reproducible
(a test fails when a committed file is stale, so run the generator after changing `tools/models/`).

| Command | Writes |
| --- | --- |
| `node tools/make-models.mjs` | `assets/models/*.glb` for every item that has a `model` field and a builder |
| `node tools/make-env.mjs` | `assets/env/studio.hdr` (13 KB lighting map, generated, no third-party image) |
| `node tools/make-posters.mjs --chrome /path/to/chrome [name…]` | `assets/posters/<name>-light.webp`, `-dark.webp` (720x480); dev tool, needs a local Chrome (software WebGL is fine) |

For a real model: export a GLB from Blender (glTF 2.0, apply modifiers, name the theme-coloured material `accent`), compress with `gltfpack -cc` (Meshopt) or Draco,
aim for 1–2 MB, put it in `assets/models/<name>.glb`, set `"model"` and run `tools/make-posters.mjs` to get its posters. Draco/KTX2 need their decoder files in
`assets/vendor/` (see `assets/vendor/README.md`). Meshopt needs nothing extra.

Tests (no browser needed): `node --test` from the repository root. It also runs the Python tests of the admin library, the installer tests (fake nginx/uhttpd, needs `sh`),
the deploy script tests and the model structure tests.

## Deploy to Cloudflare Pages

`deploy.sh` publishes only the public site (`index.html`, `assets/`, and
`data/`) to an existing Cloudflare Pages project. It deliberately does not
publish this README, the deployment script, or any local notes.

One-time Cloudflare setup:

1. In **Workers & Pages**, find the old Pages project and note its project
   name. If it no longer exists, create a new Direct Upload Pages project.
2. In the Pages project, attach `viteh.org` as its custom domain. The hostname
   must no longer be routed to the Radxa Tunnel, otherwise the Tunnel wins and
   this Pages deployment will not be visible at `viteh.org`.

Then run the script. On its first interactive run it asks for the Pages project
name, then prints a Cloudflare OAuth device-login URL and code. Open it in any
browser, log in, and approve access. Wrangler saves the OAuth credentials in
the operating-system keychain; the only value stored by this project is the
Pages project name in `~/.config/viteh-site/cloudflare-pages.env`. Do not copy
that file into Git:

```sh
cd /home/unixevo/Documents/Server/viteh-site
./deploy.sh
```

Use a preview deployment before production when changing photos or copy:

```sh
./deploy.sh --preview image-refresh
```

Cloudflare prints the resulting `*.pages.dev` URL. After reviewing it, run
`./deploy.sh` without `--preview` to publish production.

The script downloads and runs Wrangler 4 through `npx`, so it needs Node.js,
npm, and an Internet connection but does not require a global installation. On
Linux, secure OAuth storage needs `secret-tool` from the `libsecret-tools`
package; Wrangler will state this if it is missing.

## Before going live

- Replace the demo email/phone in `data/site.json` and fill in the `[...]` placeholders in `legal` (Impressum / Datenschutz).
- The contact form is a demo and sends nothing. Connect it to email, Telegram or a small backend when ready.
- Example projects in `data/products.json` are demo content; replace them with real case studies.
- Content is rendered by JavaScript. For stronger SEO, consider pre-rendering per language at build time.

## Project archive 2022–2025: how to add the pictures

Slots are listed in `data/portfolio-images.json` (`status: "placeholder"` until a picture arrives). Visitors never see a placeholder: the slot is simply skipped.
Preview with the red PLACEHOLDER boxes: `node tools/make-portfolio-placeholders.mjs`, then open `index.html?slots` on a local server.

Put the finished pictures in one folder (as `<folder>/<slug>/<slot>.jpg`, `<slug>-<slot>.png`, or under the original file name from `source_hint`) and run:

```bash
node tools/portfolio-images.mjs ~/my-pictures
```

The importer crops to the slot ratio (rejects a picture that is more than 15 % off), compresses to WebP + JPEG of at most 200 KB, writes `assets/portfolio/<slug>/<slot>.*` and sets the slot to `final`.
Then rebuild the PDF: `node tools/make-portfolio.mjs --final` (fails while any slot is still a placeholder; `--slots` draws the missing ones as PLACEHOLDER boxes for review).
Privacy is the owner's last check: crop photos to the device, no names, addresses, IP/MAC, passwords or contracts, test data only in Windows screenshots.
